## The source

Obserwator's feedback #11 (2026-11-23): „Obserwator jako wtyczka QGIS. Serwuje lokalizacje stacji, rodzaj, aktualne pomiary i dane historyczne, tak samo jak wersja webowa. Analizy można na razie całkowicie lub częściowo wyłączyć. Może zrobić to jako WFS?”

## Decisions of the author (2026-11-24, as relayed to this plan)

1. The plugin only connects to a server, the source of all data: no computation and nothing to download on the user's side; it is just another interface.
2. The user can change the server's address, e.g. to his own local Obserwator.
3. OGC API – Features; WFS only as a possible extension when needed, but the design must be ready for it.
4. `/api/v1` public, read-only, with limits.
5. QGIS: the latest 3.x LTR (3.44) supported, the focus on 4.x.
6. First scope: stations, current data and series in a panel, with copying values and saving CSV.
7. A user's requirement: copying water levels and discharges, and their combinations, in a form HEC-RAS or HEC-HMS accepts.
8. Answers of the same day: the plugin is „Goniec” (repository `Goniec`, QGIS folder `goniec`; „Pegaz” was the alternative, not chosen), licensed GPL-2.0-or-later; Obserwator stays MIT.
9. Later the same day, for the whole platform: „punkt dostępu i GUI hub to osobny projekt – Latarnik” and „Hydrolog powinien dostać swój serwer” (the Latarnik plan, drafted the same day). Goniec reads one discovery document from a tool's own server or from Latarnik (S4).
10. The answers to this plan's open questions (2026-11-24): „Goniec: wszystko dobowe, reszta ok”: IMGW-PIB's daily H and Q are daily values, HEC type PER-AVER (question 1); the rest as Fable recommended.

### HEC

- HEC-RAS manual, „Boundary Conditions”, the same text in 6.6 and 7.0 (https://www.hec.usace.army.mil/confluence/rasdocs/rasum/6.6/performing-a-1d-unsteady-flow-analysis/entering-and-editing-unsteady-flow-data/boundary-conditions; HEC's download page offers 7.0.2 as the current release): a flow or stage hydrograph is read from HEC-DSS or typed into a table after a „Data time interval” („Currently the program only supports regular interval time series data”) and „Use Simulation Time” or „Fixed Start Time”; „Stage and Flow Hydrograph” uses the stage until it runs out, then the flow, „primarily used for forecast models where the stage is observed data up to the time of forecast”, and „The end of the stage data is identified by the HEC-DSS missing data code of "-901.0"”; „Rating Curve”, downstream, is „a single valued relationship”, to be placed „a sufficient distance downstream of the study area”; in the table of the internal boundary's stage and flow „the end of data is a blank line. Do _not_ enter -901 in the table”. Dates are `05Jan2000`, times military, `1300` („Simulation Time Window”).
- HEC-HMS 4.14 manual, „Time-Series Data” (https://www.hec.usace.army.mil/confluence/hmsdocs/hmsum/latest/shared-component-data/time-series-data): manual entry takes the clipboard („The table includes support for the clipboard”); a missing value „should be left blank”; intervals of 1 minute to 1 day; dates `02Oct1955`, times `18:20`, „an arbitrary local time zone that does not observe summer time”, `24:00` becoming `00:00` of the next day; manual Discharge and Stage are INST-VAL, „an instantaneous measurement at the end of each time interval”; in HEC-DSS, Discharge is `FLOW` in `M3/S` and Stage `STAGE` in `M`, each PER-AVER („usually for time steps of 24 hours or longer”) or INST-VAL, a stage being „The instantaneous elevation at the end of each time interval”, under „a very strict set of rules for data type and units”; a pathname has six parts, „up to 256 uppercase characters”. HEC-HMS Known Issues (https://www.hec.usace.army.mil/software/hec-hms/known_issues.aspx): the decimal separator is chosen in the program „regardless of any setting in the operating system”, „In some countries, there will be problems when the software interacts with the clipboard of the operating system”, and „No directory or file name should use diacritic marks”. HEC-RAS users report that it needs a period as Windows' decimal symbol (http://hecrasmodel.blogspot.com/2013/06/region-and-language-settings.html; not HEC's text).
- Both read HEC-DSS natively. HEC's `hecdss` (PyPI 0.1.33 of 2026-08-28, MIT) wraps the native library through ctypes; its wheel carries `hecdss.dll` and `libhecdss.so`, both x86-64, and no macOS or ARM library; it writes DSS 7 only („Only version 7 DSS files are supported”) and writes a missing value as `DSS_UNDEFINED_VALUE`, −3.4028·10³⁸ (`hecdss.py:22`), not as HEC-RAS's -901.0.

## Design

### Goniec: a shell and modules

Goniec is a shell plus one module per kind of server. The shell holds what every module shares: server connections and their authentication, attribution and regulamin, HTTP caching, settings, the CSV, clipboard and HEC exports, and the panel framework. A module is shown only when the connected server advertises it: at connection the shell reads the server's version and capabilities (S4), and QGIS reads the OGC conformance for the layers. Goniec 0.1 has only the Obserwator module.

### The server: Obserwator

S1. **OGC API – Features** at `/ogcapi/` of `obserwator server`: landing page, `conformance`, `api` (OpenAPI 3.0), `collections`, `collections/{id}/items`, `items/{featureId}`.
- Conformance: Part 1 Core, GeoJSON and OpenAPI 3.0, in CRS84; QGIS reprojects the points itself. Part 2 (EPSG:2180) only when a client needs it, with a reprojecting dependency; Part 3 filters later.
- Collections: `stations-<provider>`, one per served provider, a point per station with the catalog's properties (the code as `featureId`, name, kind, river, hydrographic code, river km, catchment area, gauge zero and its datum, the datasets with series); `latest-<provider>-<kind>`, one per provider and kind with current data, the station's point with its last readings (time in UTC, value and unit per variable, tier, time of the server's snapshot).
- Paging by `limit` (default 1,000, maximum 10,000, so one page holds a provider's stations) and `next` links with `numberMatched`; `bbox`. The instance filter applies (ADR-025 D3): only served providers have collections, clipped stations are absent, a private capture has none (ADR-030 D5).
- Each collection's `description` carries its provider's lines — a `latest-*` one's first the words „dane operacyjne, niezweryfikowane” (DEV-20.8) — and its `rel="license"` links the terms, so QGIS fills the layer's abstract and licences even without Goniec; each `items` answer carries `attribution` and `terms_notice` beside `features` (DEV-20.5).
- Ready for WFS: one feature source per collection, flat properties (lists as text, no nested objects), stable collection and feature ids, so a WFS 2.0 endpoint can later serve the same collections as feature types.

S2. **`/api/v1` public and read-only** under a setting of the REST server, `api_public`: every POST, `?check=true` included, is `forbidden`; a command that calls a provider (`network: true`) is public only through the server's own cache of bounded age, never as a pass-through per request (as the Latarnik plan proposes for every tool): `current *` from a snapshot of at most 600 s and `pmaxtp fetch` from the cache of a day per point, the GUI's code (`gui/_live.py`) shared by both servers; `stations find` with `source=live`, its default, and `store check` are refused; `stations find` with `source=store`, which reads the data root's catalogs and calls no provider (Facts), the station collections and `stations export` serve the catalog. Each client address is limited as DEV-15.9 (`request_limit`, `request_window`; 429, `Retry-After`, `rate_limited`), the address taken from `X-Forwarded-For` only from the local proxy, as both servers already do (Facts); `limit` stays capped by `OBSERWATOR_API_MAX_LIMIT`; logs keep no address (DEV-15.10); CORS stays closed (Goniec is no browser). Until Latarnik routes it, the public host sends `/api/v1/*`, `/ogcapi/*` and `/health` to `obserwator server` and the rest to `gui serve` (the tunnel's path rules).

S3. **Caching by resource class.** Strong, quoted ETags of what an answer was made from, each with the package version (`API_VERSION`) and a digest of the answer's lines (`attribution`, `terms_notice`), as the GUI's ETag holds the server's run, so a release or a change of the lines is a new ETag; `Vary: Accept-Encoding, Accept-Language`; `public` only with `api_public`, else `private`; no class is `immutable`, since the bytes of a stored version carry lines and a format that a release can change.

| Class | Answers | ETag from | Cache-Control |
|---|---|---|---|
| Server | `/api/v1/server`, `/health` | instance key, regulamin version | `no-cache` |
| Catalog | `stations-*`, `stations export`, `datasets list`, landing page, `collections` | catalog versions (`2026-11-22_4808b177`), instance key | `max-age=86400` |
| Versioned series | `series read`, `export`, `hec` naming a store version | version and query | `max-age=86400` |
| Current series | the same without a version | version and query | `max-age=3600` |
| Current data | `latest-*`, `current *` | the snapshot's serial | `max-age` = the snapshot's remaining life, ≤ 600 |
| Errors, refusals, 429 | all | none | `no-store` |

Goniec reads a series by the version `series select` names, so what it reads changes only with a release or the lines, and its cache revalidates a day later for a 304. Qt's cache keys on the URL alone, with no `Vary` handling, and keeps a `no-cache` answer to revalidate it (Facts); Goniec therefore sends one `Accept-Language`, QGIS's (`pl` or `en`), on every request.

S4. **Version and capabilities.** `GET /api/v1/server` answers `nogat-server/1`, a schema in Nogat's `schemas/exchange/` (additive within `/1`, AGI-4.1), on a tool's own server and on Latarnik alike (the author, 2026-11-24: „punkt dostępu i GUI hub to osobny projekt – Latarnik”; the Latarnik plan takes the same path), so a client needs one address and one GET: `services`, a list with one entry for a tool's own server and several behind Latarnik, each `tool`, `version`, `api` (each served major with its base path: `{"1": "/api/v1"}` on the tool's own server, `{"1": "/obserwator/v1"}` behind Latarnik, so a `/api/v2` is listed beside v1), `capabilities` (`stations`, `current`, `series`, `hec-table`, `hec-dss`, `analyses`, each only when served), `ogcapi` (the landing page), `instance` (title, featured provider), `terms` (the regulamin's address and version), and the served providers' `attribution` and `terms_notice`. A client reads the same document from either, so Goniec needs no change when an address moves behind Latarnik. The schema is written once, by whichever of this plan's N1 and the Latarnik plan's Nogat step comes first, with the fields of both (that plan adds `gui` per service, and `release_set` and `flows` on Latarnik); the other adds its fields additively. `/api/v1` changes only additively (ECO-085); a breaking change is `/api/v2`, served beside v1 for at least one minor.

S5. **HEC export on the server**, a catalog command `series hec` (CLI, REST, MCP and Python; ADR-002) with the options of `series export` — `station`, `dataset`, `version`, `start` and `end` (AGI-3.4), `variables` (`Q`, `H` or `H,Q`) — and its own: `program` (`ras`, `hms`), `form` (`table`, `dss`), `stage` (`elevation`: m in the datum of the gauge zero, the default where the catalog has one; `gauge`: m above the zero, the default elsewhere) and `tz` (`UTC` by default, as Obserwator, so a HEC table, a CSV and the panel carry the same stamps; `UTC+01:00` without summer time on request, for sub-daily series only; open question 2), the zone named in every envelope. The server converts and checks; Goniec only copies or saves the answer.
- **Types and stamps.** A dataset's HEC type is recorded in the catalog (an optional field, AGI-4.1) and named in every answer: INST-VAL for the hours of IMGW-PIB and of ČHMÚ's `recent`, full-hour records stamped at their `time` (ADR-031 D3); PER-AVER with the interval `1DAY` for every daily series, ČHMÚ's daily means and IMGW-PIB's daily H and Q alike (IMGW-PIB's by the author's decision of 2026-11-24, open question 1), stamped at the end of their day (`2400`, in HEC-HMS `00:00` of the next day). A daily series keeps its source's day; `tz` moves the stamps of sub-daily series only.
- **Stage.** HEC's stage is an elevation (HEC-HMS: „The instantaneous elevation at the end of each time interval”), so `elevation` adds the gauge zero to H and the envelope names the zero, its datum as the station page names it and the date of that page: Obserwator knows no earlier zero, and a period before a change of the zero is shifted by it (Facts). With `gauge` the envelope says that the values are not elevations.
- **Tiers (DEV-20.8).** The answer names the tiers of its values; where any is not `verified`, the panel shows „dane operacyjne, niezweryfikowane” beside the copy and save buttons, and a DSS record's F part ends with `DANE OPERACYJNE NIEZWERYFIKOWANE`.
- `table`: tab-separated values in SI with a decimal point, the series' own regular interval (`1DAY` or `1HOUR`), no header; the envelope gives the start, interval, count, units, HEC type, tiers and stage form that the panel shows for HEC's editor, the start in each program's form: HEC-RAS's „Fixed Start Time” a date `05Jan2000` and a military time `1300`, HEC-HMS's time window `02Oct1955` and `18:20`. HEC-RAS: Flow, Stage, or Stage and Flow (two columns, the stage first), which HEC-RAS uses as the stage until it runs out and the flow after it, „primarily used for forecast models”: the stage may end before the flow, its cells blank after its last value (the editor's end of data); a gap inside a column refuses the table, naming the first missing time. HEC-HMS: one column, Discharge or Stage, a gap an empty line („should be left blank”). The panel names the decimal point, which HEC-HMS takes by its own setting and HEC-RAS by Windows' regional settings (Facts); `dss` is the way round a paste that fails.
- Rating curve for HEC-RAS: not in O1 or in Goniec 0.1 (open question 3); it comes with Goniec's Hydrolog module (Later modules), as stage–discharge pairs tabulated from the `rating_curve` analysis of the chosen years, single-valued and sorted by stage, the stage in the form the option `stage` names; never the raw daily pairs; its envelope says that the curve is fitted to daily pairs, not to measurements (`instrukcja/index.html:390`), and that HEC-RAS wants it „a sufficient distance downstream of the study area”.
- `dss`: one DSS 7 file in a ZIP with `ATTRIBUTION.txt` (DEV-20.5: ZIP, model inputs), both named in ASCII by `obserwator._file_names` (DEV-19.21; HEC-HMS cannot process file names with diacritic marks), written with `hecdss` as the optional extra `obserwator[hec]` (x86-64 Linux and Windows only, as its wheel's libraries; without it `hec-dss` is not advertised); the pathname in upper case and at most 256 characters, `/<RIVER>/<CODE> <NAME IN ASCII>/FLOW|STAGE/<block start>/1DAY|1HOUR/OBSERWATOR <version>[ DANE OPERACYJNE NIEZWERYFIKOWANE]/`; a stage that ends before the flow holds -901.0 after its last value, HEC-RAS's end of stage data, not `hecdss`'s missing value. Goniec writes no DSS: that needs HEC's native library, which a plugin may not carry.

S6. **The edge** (the author's instance, until Latarnik takes it): a cache rule making GET `/ogcapi/*` and `/api/v1/*` eligible, the origin's `Cache-Control` respected, „Respect Strong ETags” on, the whole query in the cache key and its Vary setting with `accept-language` normalised, since otherwise Cloudflare „does not consider vary values in caching decisions” and would serve one language to all; each deployment of a new version purges those paths, since the edge keeps a copy to its `max-age` whatever the new ETag; on the zone's Free plan (open question 5), one rate-limiting rule per IP over both paths with a period of 10 s, which only cuts floods before the tunnel, its threshold above a layer's paging since cached answers count on Free; the limit that counts is the origin's per address (S2, DEV-15.9), and Pro only if D1's logs show abuse that the origin's limit lets through; Access in front of `/admin` as today.

### Goniec

G1. **Connections.** The author's public instance by default (Latarnik's address once it exists); any other address, e.g. one's own `obserwator server` on 127.0.0.1. A connection is a name, an address and an `authcfg` of QGIS's auth manager (Basic, OAuth2, or API headers such as a Cloudflare Access service token's two) for an operator's private instance; Goniec stores no secret. At connection it reads `nogat-server/1` at `/api/v1/server` of the address and shows a module per listed service it knows: an unknown `tool` is skipped, a service whose `api` lists no major it speaks is refused with both versions named, and a capability the server lacks hides its part of the panel.

G2. **Network and cache.** Every request goes through `QgsNetworkAccessManager` (proxy, auth, disk cache) with `PreferNetwork` and one `Accept-Language`, QGIS's: the disk cache serves what is fresh and revalidates the rest by ETag (304, no body). The map layers are QGIS's own OAPIF layers of the server's collections, so a project stays portable and anyone can add them through „WFS / OGC API – Features” without Goniec; Goniec sets a `latest-*` layer to reload its data every 600 s (`Qgis::AutoRefreshMode::ReloadData`), since the provider keeps a layer's features until they are reloaded. Per server and catalog version Goniec keeps the station collections as served (GeoJSON, unprocessed) in its cache directory, for the panel's search and list and for the last known stations, marked as such, when the server cannot be reached; a new catalog version replaces them.

G3. **The panel, 0.1** (the Obserwator module): stations (search by name, code or river; a click on the map), the station's description, current readings, a series (dataset, variables, period) as a table; „Kopiuj” (the values shown, tab-separated); „Zapisz CSV” (the bytes of `series export` under the server's file name, DEV-19.21); „Kopiuj do HEC-RAS” and „Kopiuj do HEC-HMS” with the editor settings, the stage form and the tiers shown beside them (S5); „Zapisz HEC-DSS” where the server has `hec-dss`. Analyses off (feedback #11); the rating-curve table comes with the Hydrolog module (open question 3); a chart is a later minor.

G4. **Attribution and regulamin.** At the first connection to a server, before any data request: the server's title, its providers' lines and a link to its regulamin, confirmed once per server and regulamin version. Each layer carries the lines in its metadata (abstract and licences from the collection, rights and attribution set by Goniec). The panel shows a strip with the lines of what it shows, „Źródła i warunki” and „Regulamin”. Saved files are the server's bytes with their lines. The clipboard holds values only, since a paste target takes nothing else; the lines stay beside the buttons and in every saved file (a DEV-20.5 row, N1).

G5. **Versions and packaging.** `qgisMinimumVersion=3.44`, `qgisMaximumVersion=4.99`, Qt only through `qgis.PyQt`, tested on 3.44 (the LTR) and 4.4 (the latest release and the next LTR) on Linux and Windows; the description names macOS as untested, since plugins.qgis.org asks for all three platforms and for restrictions in the description; a minor after 4.4 replaces 3.44 in the long-term repository (4.4.4: 2027-03-26 with 4.6.0 in the roadmap, 5 March 2027 in the blog of 2026-10-03) may drop 3.44. No third-party runtime dependency and no binary; README and CLAUDE.md name QGIS and PyQt as its GPL dependencies (DEV-13.5). Polish UI through Qt translations, English code and docs (DEV-2.1, DEV-2.2), an English description for plugins.qgis.org. GPL-2.0-or-later, stated in Goniec's first ADR (DEV-16.1); uv for development tools only; released as a ZIP of `goniec/` to plugins.qgis.org, 0.x marked experimental.
