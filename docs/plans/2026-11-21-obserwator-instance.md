## The author's direction (2026-11-21)

- A potential client wants Obserwator on his own infrastructure and has his own measurement network.
- The GUI must let one provider's data stand out and make it easy to control the visibility and the availability of the other sources; a view limited to a chosen area, or a start zoomed to the chosen provider's stations instead of the whole data set, is wanted.
- Obserwator stays the single source of code: clients update it through git. A deployment's choices live in separate files (environment or configuration), never in code.
- Security, running on someone else's infrastructure, portability, data security and sign-in security are of the highest importance.
- For now the clients' data are public and the client wants a better interface of his own. If data become private and must be closed, the whole instance goes behind SSO or Cloudflare Access; Obserwator gets no accounts.

## The author's answers (2026-11-21)

- Keys: „Zatwierdzam klucze wg rekomendacji”: the unused `obserwator admin keys` goes; one write token and one admin key stay, from files of mode 0600 and at least 32 bytes; `/admin` behind a rule of the edge on every instance.
- Commercial use: payment is only for the deployment; operating the instance is the client's, outside the author's work. The regulamin is the client's too; the author may only prepare a draft that protects his interests.
- The client's name and logo on the instance: yes.
- PMAXTP: a switch of its own.
- The client's network: the class `other`.
- The instance's filter applies to both servers, the GUI's and the REST API (I3).
- Symbols and the featured provider (later the same day): „w naszej instancji ujednolicić … źródła nie będą mieć unikalnych symboli”: every provider's station is drawn by its kind only (hydro, meteo), ČHMÚ's dashed outline goes; on an operator's instance the featured provider's stations stand out and the rest are faded, the legend groups „Stacje: <dostawca>” and „Pozostałe źródła”, and the fading is a setting (`others_opacity`, 0.1 to 1.0, default 0.4). The kit's order of the strip's lines stays (I6 amended; Obserwator ADR-025 erratum of 2026-11-21, `develop` `50c7749`).

## Goal

1. One file section describes an instance: which providers it serves, which one it features, its area and its start view, its title. The same code serves the author's public instance and every client's.
2. What an instance does not serve is filtered on the server, at one place, for every route: never only hidden in the browser.
3. An instance starts only from a valid description (fail closed) and reports it in `config show` and `api/session`.
4. A client can run, move, back up and update an instance on his own infrastructure from a git tag, with a written threat model and no secret in any tracked file.
5. In `v3.3.0` (moved from `v3.2.0` by the author on 2026-11-22, beside Gdańskie Wody and the GUI of the source classes), the client's own network enters as data, not as code: a file-fed provider (step 6).

## Design decisions [proposed]

| ID | Decision |
|---|---|
| I1 | **The instance section.** `[obserwator.instance]` in `nogat.toml`, read at start (DEV-18.1); no credential in it (DEV-18.4). Fields: `title` (the operator's name in the page title and the header, optional), `logo` (a path to the operator's logo, optional, I14), `featured_provider` (a provider id, optional), `start_view` (`all`, the default, `featured` or `area`), `area` (a path to a GeoJSON file, optional), `area_mode` (`focus`, the default, or `clip`), `pmaxtp` (`on`, the default, or `off`, I8), `terms` (a path to the operator's regulamin in Markdown, optional, I15), and the table `[obserwator.instance.providers]` mapping a provider id to `visible` (the default for every provider), `hidden` or `off`. Without the section an instance behaves exactly as today. |
| I2 | **Three provider states.** `visible`: served and shown. `hidden`: served, but off in the GUI's default filters; a person turns it on. `off`: not served at all, so absent from the station layer, series, analyses, exports, hand-offs, current data, the attribution strip, the „Źródła i warunki” dialog and the regulamin's source blocks, and the server makes no request to that provider. The featured provider cannot be `off`. |
| I3 | **One filter on the server.** The data root's snapshot (`gui/_root.py`) is reduced once, after each read, to the instance's providers and, with `area_mode = "clip"`, to the stations inside the area; every route reads that reduced snapshot, so the station layer, its ETag and every station route agree. A station outside the instance answers `not_found` (no leak through a guessed code). The REST server (`obserwator server`) applies the same section; the CLI and MCP, local tools, do not. |
| I4 | **The area.** One Polygon or MultiPolygon in WGS84 (RFC 7946), at most 1 MB and 100,000 vertices, read once at start. `focus`: nothing is removed; the outline is drawn and the map starts on it. `clip`: stations outside are removed by I3, and the map's bounds are the area's box with a margin. No buffer: the operator draws the polygon he means. |
| I5 | **The start view.** `featured`: the box of the featured provider's stations after I3, with a margin; `area`: the area's box; `all`: today's. A start view with nothing in it falls back to `all` and logs a warning. |
| I6 | **The featured provider stands out.** Its stations are drawn above the others at full strength; the others are drawn smaller and faded (`others_opacity`) while „Pokaż inne źródła” is off, its default on an instance with a featured provider; the legend groups the featured provider's stations and „Pozostałe źródła”, and no provider has a symbol of its own (the author, 2026-11-21). The left panel lists the featured provider first, above the class headings of `hydromet-providers` P12, so the two designs fit; the strip keeps the kit's order of the lines. Without a featured provider the GUI is today's. |
| I7 | **Fail closed.** An unknown provider id, a featured provider that is `off`, an area file that is missing, too large, not a polygon or not in WGS84 range, or an unknown field is `validation_error` (exit 2) at start, with `details.option` naming the field; the server does not start. `config show --json` reports the resolved section; `api/session` reports what the page needs (featured provider, start box, area outline in `focus`/`clip`, title), never a path. |
| I8 | **Outbound requests follow the settings.** Each source the server contacts is listed in USAGE with the setting that turns it off: IMGW-PIB's current data follow the state of `IMGW-PIB` (`off` makes no request); PMAXTP has its own switch `pmaxtp` (the author, 2026-11-21), so an instance may serve PMAXTP without IMGW-PIB's stations or the reverse; the basemap follows `OBSERWATOR_GUI_BASEMAP_URL` (a self-hosted TileJSON or `none`). |
| I9 | **No accounts.** Obserwator gets no sign-in and no roles. A private instance runs entirely behind the operator's SSO or Cloudflare Access at the edge (`install-contract` rule 12); the admin panel keeps its key and, on every instance, a rule of the edge in front of `/admin`, `/admin/*` and `/api/admin/*`. |
| I10 | **Secrets and files** (the author, 2026-11-21: keys as recommended). Credentials only as `OBSERWATOR_*_FILE` (or the variable), files of mode 0600 owned by the service user; `.env`, `*.key` and `api_keys.json` are ignored by git. One admin key (the GUI's `/admin`) and one write token (REST writes) stay; neither is a user or a role. The command `obserwator admin keys` and its `api_keys.json`, which nothing checks, go. From 1.0 only a major may break (REL-1.1), so `v3.1.0` deprecates them (the command says on every call that its keys are checked by nothing and are removed in `v4.0.0`; `config show` reports a leftover `api_keys.json` as a problem) and `v4.0.0` removes them. Likewise a key or token shorter than 32 bytes or a key file readable by others is a warning (a log record and a `config show` problem) in `v3.1.0` and refuses the start from `v4.0.0`; with an `[obserwator.instance]` section, new in `v3.1.0`, it refuses the start at once, since no deployment depends on it yet. A deployment's own files (`nogat.toml`, the area, the logo, the regulamin, the secrets) live outside the checkout, under `/config` in a container (`install-contract` rule 4). |
| I11 | **Threat model.** `docs/SECURITY.md` gains a threat model of an instance on foreign infrastructure: assets (the data roots, the secrets, the feedback reports, the logs), entry points (the GUI's private API, the REST API, the admin panel, the outbound fetches), the trust in the reverse proxy (one variable of trusted proxies), what the operator must provide (TLS at the edge, the edge's rules, backups, updates in the maintenance window) and what Obserwator guarantees. |
| I12 | **Update and move.** A client pins a tag (`uv tool install "obserwator[gui,api] @ git+…@vX.Y.Z"` or the image of `install-contract` S4), never a branch. At start the server checks that the data root's layout version is one it reads and refuses otherwise with a hint; moving an instance is copying its two roots (`rsync -aH`, DEV-18.5), its `state_dir` and its `/config`. USAGE gets one section „Deploying an instance for an operator”; the Polish runbooks of a client live in the private deployment repository (`install-contract` S5). |
| I13 | **The operator's own network (`v3.3.0`).** A provider fed by files, not a client's module: a station catalog (GeoJSON of the documented fields) and series in `obserwator-series-csv` or Parquet, imported by one command into the stores, with the provider's id, name, country, source class `other` (`hydromet-providers` P11; the author, 2026-11-21), licence and attribution line declared in a provider file beside `nogat.toml`. It is one adapter of P1, so no `if provider == …` appears; adding a client is configuration and data. |
| I14 | **The operator's name and logo** (the author, 2026-11-21). `title` names the operator in the page title and the header; `logo` is the operator's logo in the top bar beside Obserwator's mark, which stays (favicon and top bar, DEV-15.3), so the operator's mark never replaces Nogat's. The logo is PNG, WebP or SVG, at most 200 KB, checked at start (type by content, size); the server serves it from its own origin (no new CSP origin), an SVG with `Content-Security-Policy: sandbox; default-src 'none'` and `X-Content-Type-Options: nosniff`, so a script in it never runs. DEV-15.3 gets an amendment for an operator's mark (Nogat, step 1). |
| I15 | **The regulamin of an operator's instance** (the author, 2026-11-21). The operator writes and publishes his own; the instance serves it from `terms` in place of Nogat's regulamin 1.0, which names the author as the operator and stays for the author's instances. Nogat's kit gets a draft template for operators (step 1), written to protect the author as the author of the software and the one who deployed it: the operator is the service provider and the controller of personal data; the software is provided as is under the MIT licence, without warranty or liability for availability, data or results; the data sources' terms (DEV §20) are the operator's to keep; the author's part ends with the deployment. The draft is marked as a template, not legal advice; a lawyer of the author's choice reviews it before a client gets it. |

## Steps (producers first)

1. **Nogat:** this plan; `ecosystem.yaml` notes the instance section in Obserwator's interfaces; the DEV-15.3 amendment for an operator's mark (I14); the draft regulamin template for operators in the kit (I15); PROGRESS.
2. **Obserwator, ADR „instance”** (I1, I2, I7, I10): settings, validation, `config show`, `.env.example`, messages pl/en, the length checks of the secrets, `.gitignore`.
3. **Obserwator, the server's filter** (I3, I4, I8): the reduced snapshot, the REST server, the outbound switches; tests that an `off` provider and a clipped station are absent from every route and that no request leaves for an `off` provider.
4. **Obserwator, the GUI** (I4 to I6): start view, featured drawing, „Pokaż inne źródła”, the area's outline and bounds, the title; the attribution strip and the regulamin's source blocks of the served providers only; browser tests of each state.
5. **Obserwator, documents** (I11, I12): `SECURITY.md`, USAGE „Deploying an instance for an operator”, the layout-version check; a demonstration instance on this machine (a featured provider and an area, `clip`), smoke-checked on 127.0.0.1.
6. **Obserwator `v3.3.0`, the file-fed provider** (I13), on the adapters of `hydromet-providers` steps 2 and 3 (in `v3.2.0`), beside Gdańskie Wody (the author, 2026-11-22: „też przenosimy do v3.3.0”).
7. **Nogat:** registry drift, the release set of the round, PROGRESS.

- Steps 2 to 5 (2026-11-21, Obserwator `feat/operator-instance`, merged into `develop` at `9b920f8`; ADR-025): `obserwator.instance` reads and checks `[obserwator.instance]` at the start of both servers (`validation_error`, exit 2, `details.option` `instance.<field>`); one filter reduces each read of the data root in the GUI (`DataRoot._read`, the key folded into the station layer's ETag) and guards every route of `/api/v1`, so an `off` provider and a clipped station answer `not_found` like an unknown code and no request leaves for an `off` IMGW-PIB or with `pmaxtp = "off"`; the page starts on the featured provider's or the area's box, draws the area and keeps to it in `clip`, fades the others behind „Pokaż inne źródła”, shows the operator's title and logo (`api/logo`, an SVG under `sandbox`) and serves the operator's regulamin with the served providers' source blocks; `OBSERWATOR_STORE_WRITE_TOKEN_FILE`; weak secrets and a leftover `api_keys.json` are `config show` problems (start refused only with an instance); `obserwator admin` deprecated, removed in `v4.0.0`; a root of an unknown layout refused at start; `SECURITY.md` threat model and USAGE „Deploying an instance for an operator”. Open for the author: the featured provider's lines first in the kit's `<nogat-sources>` (a kit change); a lawyer's review of the draft regulamin.
- Step 6, Nogat's part (2026-11-23, `feat/camels-pl-and-provider-lines`, ECO-087): the kit's `<nogat-sources>` showed on the strip only the lines it knows, so the line of the provider fed by files (I13) would have reached only the dialog (Obserwator's `docs/PROGRESS.md`, „Open questions”).
