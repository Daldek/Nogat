| B1 | **One catalogue, library-neutral.** `design/kit/nogat-basemaps.json`, data a server reads (its CSP, its regulamin's blocks, the check of its setting) and a page receives from its server: Hydrograf's set, ids, labels and order (`layers.js:62-67`). `openfreemap`, „OpenFreeMap szary”: vector, the TileJSON `https://tiles.openfreemap.org/planet` (Obserwator's and Archiwista's address; Hydrograf's `styles/positron` goes, B4), blocks `osm`. `gugik-osm`, „OSM GUGiK szary (tylko Polska)”: raster XYZ of `layers.js:22`, zoom 0–19, grey, bounded by the box of Poland as the orthophoto is (today unbounded), blocks `osm` and `gugik`. `gugik-ortho`, „Ortofotomapa GUGiK”: raster WMTS KVP of `layers.js:47-50`, zoom 0–19, bounds 13.8–24.4° E, 48.8–55.0° N, block `gugik`. Each entry: `id`, `label`, `kind` (`vector` or `raster`), `url`, `origin`, `minzoom`, `maxzoom`, `bounds`, `grey`, `credit` (B5: its text and the links in it), `blocks`. „bez podkładu” is no entry: the switcher's last choice, always. No entry needs a key; no Esri (ECO-068); no topographic map (open question 5). |
| B2 | **One module in the kit, as two files.** `design/kit/nogat-basemaps.js` and `design/kit/nogat-basemaps.css`, a plain ES module that imports nothing (as every kit script, and as `plan/unified-charts` C1), so a GUI that loads a kit file by its hash (Hydrograf's `?v=`, `js/nogat.js`) meets no other version behind it; the map library is passed in, never imported. ### The map library: two ways weighed

| | A: one library, MapLibre 6.14.0 in every GUI | B: the catalogue and two thin adapters (recommended) |
|---|---|---|
| What moves | Hydrograf off Leaflet: `js/map.js` (1,406 lines) and `js/layers.js` (782) with its panes (`map.js:185-200`), its own wheel handler, VectorGrid's streams and sewer tiles, the DEM, land cover and result tile layers, the WMS of the MZP, the profile's marker and the admin dialog's map | data, a switcher and two functions in the kit; Hydrograf keeps Leaflet and draws the vector base map through `maplibre-gl-leaflet` as today |
| Base maps alike | yes | yes: same entries, labels, order, style, credit, CSP and blocks; one test set per adapter |
| Interaction alike | yes, a map shell can follow | no: Leaflet's and MapLibre's gestures stay each GUI's, outside this plan |
| Cost | a rewrite of Hydrograf's map before its base maps can be shared | one adapter more in the kit (about a raster `tileLayer` and the vector style handed to `L.maplibreGL`) |

The author asked for shared base maps, not for one map: B does that in every GUI's next minor and leaves A, which the GUI platform plan already parked (`2026-11-01-nogat-gui-platform.md:453`), to a plan of its own (open question 1). With `plan/unified-charts` it shares the approach (a script and a stylesheet of the kit that import nothing, Polish words exported and replaceable, the library or language passed in, browser tests under the GUIs' CSP, a rule of DEV §15 and one decision, the producer first, each GUI in its next minor, a deviation until then); it differs in one point: the chart module draws the charts, so Hydrograf leaves Chart.js there, while this module draws only the base map on the GUI's map, so the library stays the GUI's.
