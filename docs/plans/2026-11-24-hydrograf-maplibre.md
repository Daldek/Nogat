## Can it move? Feature by feature

MapLibre 6.14.0 as vendored by Obserwator (`maplibre-gl.mjs`, `maplibre-gl-worker.mjs`), read on 2026-11-24.

| Feature | Today | On MapLibre 6.14.0 | Blocks? |
|---|---|---|---|
| Loading | classic scripts, a global `L` at once | an ES module and a module worker only, loaded by `import()` (a classic script may call it), so the map is ready later than the page's scripts; `worker-src 'self'` instead of `blob:` | no: `Hydrograf.map.init` returns a promise the other modules wait for (M1) |
| MVT styling | VectorGrid's JavaScript style functions per feature | `vector` sources and `line`, `fill`, `circle` layers with expressions: `interpolate` over `log10` (present in the bundle) for streams, `match` for land cover and sewer; opacity and theme by `setPaintProperty`, no redraw | no (M5). Vector sources must be 512 px („vector tile sources must have a tileSize of 512”), so at one scale MapLibre asks tiles one level lower than VectorGrid's 256 px: four times the area per tile from the dynamic endpoint (Risks) |
| WMS raster | `L.tileLayer.wms` | a `raster` source with a GetMap template and `{bbox-epsg-3857}` (present in the bundle; Archiwista's `tileUrl`), 512 px; a layer's `minzoom` does not hold the map's zoom | no (M7). MapLibre fetches tiles and uploads them to WebGL, so each provider must send CORS: on 2026-11-24 the MZP WMS, GUGiK's orthophoto WMTS, GUGiK's OSM tiles and OpenFreeMap all answered `Access-Control-Allow-Origin: *` (curl with an `Origin` header) |
| Other raster | DEM tiles, results' tiles, two `imageOverlay`s | `raster` sources with `bounds`, `minzoom`, `maxzoom`; `image` sources by four corners | one gap: Leaflet's `minNativeZoom` draws a result's first level scaled down below it; MapLibre draws a raster source only from its `minzoom` (`coveringTiles` skips the tiles under it, read in 6.14.0) (open question 4) |
| Drawing tools | Hydrograf's own (no Leaflet.draw): profile line, admin box | map events with `lngLat`, `project` for pixel distances, `doubleClickZoom` and `dragPan` toggled, a GeoJSON `draw` source, as Archiwista's `draw.js` | no (M10) |
| Draggable points | `L.marker` with `draggable`, `autoPan` | `Marker` with an element and `draggable`; no `autoPan` in the bundle | small gap: no pan at the map's edge while dragging (open question 5) |
| Popups, tooltips | three tooltips, no popup | hover by `mousemove` with `queryRenderedFeatures`; one `Popup` without a close button, restyled | no (M9) |
| Panes → order | panes by z-index, GeoJSON in insertion order | one ordered list of style layers, each added before a named slot; DOM markers above the canvas | no (M4); the order becomes explicit, the same as today |
| Controls, legends | `L.control`, `L.DomUtil`, `.leaflet-*` CSS | `IControl` (`onAdd`, `onRemove`) in the same corners, plain DOM, `.maplibregl-ctrl*` CSS | no (M11) |
| Wheel zoom | Hydrograf's own handler against whole-level steps | MapLibre zooms by fractions; the handler goes, and the admin map's backlog item with it | no |
| Zoom numbers | Leaflet's, a world of 256 px | a world of 512 px: the same scale is one zoom less | no, but every number moves (M3) |
| Print, export | none | none planned; a PNG of a WebGL map would need `preserveDrawingBuffer` or a capture in `render` | nothing to port |
| Phone | one-finger pan, pinch, tap, the drawing buttons | the same with rotation and pitch off (Obserwator's options); taps are clicks within `clickTolerance` | no; WebGL 2 required (next row) |
| WebGL | 4.7.1 asks `webgl2`, then `webgl`; without either only the vector base map fails, Leaflet still draws everything | 6.14.0 asks only `webgl2`, and `new maplibregl.Map` throws `GPUInitializationError` synchronously without it | a browser without WebGL 2 gets no map (M13, Risks). WebGL 2 is in every major browser since February 2022 (https://www.khronos.org/blog/webgl-2-achieves-pervasive-support-from-all-major-web-browsers), on iOS since Safari 15 |
| Backend tiles | `ST_AsMVT`, pre-generated `pbf` from level 8 (`generate_tiles.py:41`), the sewer served from level 10 (`tiles.py:248-250`) | the same API; the tiles asked one level lower at the same scale, so the pre-generated set starts at 7 (threshold 1000 at 13) and the sewer at 9, or every tiled vector layer appears one scale step later than today | no, a backend change in step 2 (M5) |

**So the move is possible**: nothing of Hydrograf's map lacks a counterpart in MapLibre 6.14.0, and no third-party service stands in the way. The cost is a rewrite of the map code (about 110 call sites of Leaflet in nine files, the 37 CSS rules, the admin dialog's map), plus five things that change: the zoom numbers (one less), vector tiles one level lower (and the backend's first tile levels with them, M5), the WebGL 2 requirement, results below their first level, and no auto-pan in MapLibre's `Marker` (written in `map.js`, open question 5).

- **Charts** (`unified-charts`, approved; Hydrograf's step 5). ## Risks

- **A rewrite without a net.** About 110 call sites in nine files, the panes, three tile kinds, WMS, drawing and the admin map change at once; step 1 is the net, which today does not exist.
- **Tile load.** At one scale MapLibre asks vector tiles one level lower, each four times the area: the dynamic `ST_AsMVT` endpoints, without simplification at query time (`tiles.py:8`), answer a quarter of the requests, each over four times the bbox; the land cover at level 7 covers the whole catchment in one or two tiles; only the sewer query has a `statement_timeout` (`tiles.py:255`), nginx cuts the proxy at 15 s (`nginx.conf:66`), and no pre-generated land cover tiles exist (`generate_tiles.py:289`, `:306`: streams and catchments only). Step 2's timing test measures the first level of each layer (7 for the streams and the land cover, 9 for the sewer) and 1:10 000, not the default view, which asks no vector tile; its budget is the p95 of today's level 8 and 10 times four at most, under the proxy's 15 s; above it, the land cover joins `generate_tiles.py` as a pre-generated layer. The `benchmark` marker is not a CI check (`ci.yml:121`), so the result is written in the step's Results.
- **WebGL 2 only.** A browser or GPU without WebGL 2 gets no map, where today it gets the map without the vector base map (M13); its panels work, and the admin dialog's four fields are filled by hand.
- **CORS of the providers.** MapLibre draws a remote image only with CORS; all four providers send `*` today, and a provider that drops it loses its layer where Leaflet's `<img>` kept it. The tests' recorded answers carry the header, so only the live services show such a change.
- **Look.** WebGL lines, dash patterns in line widths, fractional zoom blurring raster levels, the preview's pulse redrawn: screenshots of the manual and of the tests change.
- **Two plans on one frontend.** The base maps step, the chart step and Latarnik's HG1 change the same files in nearby minors; the kit's Leaflet adapter lives only from base maps step 1 to this plan's step 3.
